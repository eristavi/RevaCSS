## Standards and behavioral limits

- [CSS Overflow: native smooth scrolling](https://www.w3.org/TR/css-overflow-3/#smooth-scrolling)
- [CSS Scroll Snap](https://www.w3.org/TR/css-scroll-snap-1/)
- [CSS Transitions Level 2](https://www.w3.org/TR/css-transitions-2/)

Highlighting starts on a fragment change and can begin before scrolling finishes. Repeating the active fragment does not reliably restart it. The browser chooses scrolling duration/easing and may ignore smoothing. Scoped CSS does not configure a viewport outside its boundary. Author fixed headers/floating controls must reserve space and avoid covering focused content. Dialog invocation and application state remain application responsibilities.

## Remaining release requirements

`npm run check:release-quality` remains blocked by the six manual items in `quality/blockers.json`: nested navigation focus/assistive technology, reported edge-device behavior, current real browsers/devices, screen readers, actual zoom/text-spacing/print review, and approved per-browser visual baselines. The old 1.0.0 npm exception does not authorize 1.1.0.

Before publication, attach reproducible evidence and resolve the registry entries. Then update package/lock/release metadata to 1.1.0, rebuild and verify installed packages/download checksums, prepare matching GitHub release assets and publish npm. Verify pinned unpkg/jsDelivr links only after the package is actually available. Never replace a published 1.0.0 archive with this development build.
