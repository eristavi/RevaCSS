# RevaCSS 1.2.1 validation record

## Release scope

This release combines the 1.2 development additions and subsequent corrections: independent action materials, six palettes, sticky/flush/full navbar controls, responsive corners and a single documentation/demo settings profile. The maintainer requested version 1.2.1; existing 1.0.0 and 1.1.0 releases remain unchanged.

## Automated publication gate

The `.github/workflows/release.yml` workflow validates the final release revision before publishing a tag or assets:

- Clean CSS and documentation builds.
- Complete Node unit tests, including every palette's contrast tokens and the complete core's 17 KiB gzip budget.
- Full Playwright suite in Chromium, Firefox and Linux WebKit; all functional assertions retained and unsupported instrumentation skips reported.
- Root-path and GitHub Pages project-path documentation/link checks.
- An actual tarball installed in a clean consumer, distribution byte comparisons, public export paths, Vite and strict TypeScript.
- Installed global/scoped consumer browser checks in Chromium, Firefox and WebKit with JavaScript disabled.
- Ordinary and npm lifecycle quality gates, plus a blocking build-dependency audit.
- Reproducible ZIP/tar.gz distributions, identical starter/index pages and SHA-256 verification.

Publication runs only when every required validation job succeeds. The GitHub release links the exact workflow run; per-engine JSON reports are retained as workflow artifacts. Any unsupported native-transition instrumentation skip remains separately reported by the suite, with ordinary navigation/fallback coverage still executed. Passing headless tests does not identify a physical device or establish accessibility certification.

The previous 15 KiB core limit was exceeded after the approved six palettes and navbar additions. The 1.2.1 distribution keeps all 14 palettes built in and uses a 17 KiB limit rather than moving the added palettes into a separate dependency. The size assertion remains enforced; the limit change is disclosed in the quality standard and README.

## Regression coverage

The release tests retain the existing functional assertions and update obsolete expectations to the intentionally shared settings profile and dedicated Navbar group. New regressions cover sticky placement and anchor clearance, flush/full corner policy across global/minified/modular/scoped builds and surface materials, mobile control layout and documentation access. Navigation paint comparisons use matching pointer states. The full-page native keyboard and theme sequences use the existing 120-second documentation budget for Linux WebKit, while individual assertion waits remain bounded. Keyboard tests use Playwright-managed fixtures so teardown does not mask a body failure. Styled documentation and shared-header inventories run one route per isolated context, retaining every former group assertion while giving each route its own bounded budget and failure report. Native device navigation is checked separately for each viewport/material fixture. Animation readiness still requires two completed observations, with a ten-second bound for software-rendered WebKit; native motion and pointer stability remain enabled. No assertions are removed and no visual screenshot baseline is invented from the maintainer's statement.
