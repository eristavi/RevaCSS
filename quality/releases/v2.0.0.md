## Scope and compatibility

### Optional Svelte adapter and SvelteKit

The separate `integrations/svelte` package is an unpublished `2.0.0-dev.0`
candidate. It uses Svelte 5 runes/snippets and typed native props, with explicit
value/element bindings. CSS, tokens, core dependencies and exports stay unchanged.
On 14 October 2026, Node 24.19.0, Svelte 5.57.2, SvelteKit 3.0.1, adapter-node
6.0.0, Vite 8.3.1 and TypeScript 6.0.3 verify component/consumer types, extracted
framework tarballs, plain Svelte compilation/SSR markup and a production Kit Node
server. HTTP checks cover document themes, served core CSS, associated form
labels/messages, initial values, single/multiple selection, escaping and request
isolation. The application hook owns server theme attributes; sample theme links
use full reloads. No client theme runtime or component stylesheet is added.
Browser/hydration, interactive bindings/elements, devices and accessibility
acceptance remain deferred. The form has no submission endpoint.

### Optional React adapter

The separate `integrations/react` package is an unpublished `2.0.0-dev.0` candidate
for React 19. It compiles ESM and native prop/ref declarations without importing
CSS, using hooks or forcing a client boundary. Package extraction, strict consumer
types, a Vite production app, SSR markup and a Next.js Server Component example
are checked with locked tooling. Core CSS/tokens/exports/dependencies stay
unchanged. Browser/hydration, DOM ref/event interaction, device and accessibility
acceptance remain deferred; compilation does not establish those results.

### Optional Vue adapter

The separate `integrations/vue` package is an unpublished `2.0.0-dev.0` candidate
for Vue 3.5. It supplies typed native wrappers and application v-model bindings
without changing core CSS, tokens, dependencies or package exports. Strict Vue
component types, a packed Vite consumer and server-rendered markup are checked
with locked tooling. These checks are compilation/markup evidence; browser,
device, interaction, screen-reader and visual acceptance remain deferred.
The Nuxt reference is checked with Nuxt 4.6.1, Vue 3.5.44, Vite 8.3.4 and
Node 24.19.0 on 14 October 2026. Strict Nuxt types and the production Node server
build pass. HTTP requests to the built server verify the default/dark document
attributes, served core CSS, field labels/descriptions, initial input/textarea
values, single/multiple selections, escaping and request-local theme state.
Both framework packages come from extracted distribution tarballs; build tooling
is reused from the locked example install. No Nuxt module or adapter CSS is added.
Browser hydration, interactive models, client-navigation head updates, devices
and accessibility acceptance remain deferred. Inertia remains an integration
route without dedicated platform checks.

### Optional Astro adapter

The separate `integrations/astro` package is an unpublished `2.0.0-dev.0`
candidate for Astro 7. Build/markup checks on Node 24.19.0 and locked Astro 7.3.5
pack and extract both framework packages, compile global/scoped consumer pages,
verify native semantics, unique field IDs, merged hint/error associations, escaped
messages and absence of browser scripts. Missing field IDs fail the build clearly.
The documentation adds an Astro setup guide and navigation entry. Browser, device,
screen-reader and visual acceptance for this adapter remain deferred; existing core
acceptance does not certify the new wrappers. No CSS, tokens, runtime dependencies
or core package exports are changed by the adapter.

Default and Mono remain built in; removal of twelve previously shipped palette values is a breaking change. Follow [the migration guide](../../MIGRATION.md). Custom shape, density and page width, responsive/RTL refinements, native-input fixes and documentation accordion corrections are included. Veil remains available but deprecated. Core CSS remains independent of the optional documentation customizer and decorative demo backgrounds. Published 1.2.1 archives remain unchanged.

The readiness corrections fix the optional customizer discarding an explicit Default palette, obsolete documentation script/link expectations and version-specific release automation. Downloads include their linked guides, starter assets and package entry points, including stylesheet declarations. The framework core and its compiled CSS bytes are unchanged by this preparation PR.
