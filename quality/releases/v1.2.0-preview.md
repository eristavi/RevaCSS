# RevaCSS 1.2.0 development preview

## Button materials

The optional `reva.button-materials.css` and `reva.button-materials.scoped.css` modules add inherited `data-button-material="default|solid|glass|veil|soft|liquid"`. Native buttons, button-like inputs, `.button` links and `.scroll-top` links receive the finish. Other surfaces and fields retain their existing material. `default` restores the existing material behavior inside an explicitly configured section.

Liquid uses CSS tint, backdrop filtering, a reflective rim and a press/release scale transition. Existing `data-motion` settings control timing and movement. Reduced motion, reduced transparency, increased contrast, forced colors and print take priority, including within local settings. This is a CSS approximation, without optical refraction or pointer tracking.

The customizer, isolated previews, standalone demos, starter, module/token/attribute references and dedicated guide include the feature. Firefox scope-root guards and stylesheet invalidation prevent stale semantic/material paint. Default previews now preserve their documented size, gap and width settings when opening the customizer.

- The 61-case affected sweep passes in Chromium and Firefox, including all 18 new button-material cases. WebKit passes 60 cases and times out on a documentation inventory. Targeted reruns retain all route assertions and resolve the failures described below; this is not a claim that every final result came from one uninterrupted green sweep.
- After restricting CSS-only customizer scope guards to the HTML root, 22 selected checks pass in Chromium and Firefox. Both scripted and CSS-only material changes pass again in WebKit, as do navigation accessibility, native disclosures/popovers, the three new guide viewport checks and selected-material downloads.
- All 29 documentation inventory groups pass in Chromium and Firefox. WebKit passes every route/menu/markup assertion across the initial runs and targeted reruns: the four final large-reference groups pass after splitting them into smaller groups. All previously observed assertion failures and inventory timeouts are resolved.
- Firefox retains one existing skip for unsupported native cross-document transition snapshot instrumentation. Ordinary navigation and fallback checks run separately.
- Global/minified/scoped/modular inheritance, local overrides and resets, ordinary surface isolation, all six finishes, palette/variant paint, live changes before hover, selected HTML downloads, native interaction, disabled states, motion modes and accessibility preferences are covered.
- Rendered contrast checks sample 480 filled buttons across five explicit finishes, eight palettes, six semantic variants and light/dark themes. All sampled label backgrounds meet 4.5:1. The check found and corrected excessive Veil highlights in dark mode.
- Axe checks, 320px reflow with 200% text, RTL, CSS-only customization and unsupported-feature fallback branches pass. Instrumented fallback branches are distinguished from actual OS preference emulation in the tests.
- Core minified gzip is 15,234 bytes, below the 15,360-byte budget. The optional button-material module is 2,751 bytes gzip and remains separate from core.
- Local ZIP/tar verification checks module contents, identical starter/index pages and reproducible checksums. These are QA archives, not published releases.

Documentation inventories now run in groups of four routes with fresh pages and a 120-second group budget, preserving every route/menu/markup assertion while bounding navigation history. DOMContentLoaded is sufficient for their document assertions; fully styled pages and all assets remain available. The previous revision also renders dense reference pages slowly in Linux WebKit. The new CSS-only customizer guards explicitly qualify the HTML root to avoid unnecessary scope matching. These are diagnostic observations, not a performance benchmark or approval of real-device rendering speed. Pointer tests wait for stable geometry after native scrolling and retain their pointer activation assertions.

## Visual review and remaining release gates

Desktop and mobile screenshots were generated in all three engines for light/dark finishes and pressed Liquid buttons. Representative images from each engine were inspected; no horizontal overflow was detected.

Real Safari/iPhone touch interaction, release feel and reduced-transparency behavior still require device checks for this feature. Keyboard `:active` appearance follows the browser: Firefox on Linux can activate a button with Space without exposing its pressed CSS state. Native activation remains intact.

This is a 1.2.0 development preview. Package metadata remains 1.1.0 until release preparation; existing npm/GitHub release assets are not replaced. This record does not sign off physical-device, assistive-technology or release gates from previous revisions.
