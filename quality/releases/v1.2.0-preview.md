# RevaCSS 1.2.0 development preview

## Button materials

The optional `reva.button-materials.css` and `reva.button-materials.scoped.css` modules add inherited `data-button-material="default|solid|glass|veil|soft|liquid"`. Native buttons, button-like inputs, `.button` links and `.scroll-top` links receive the finish. Navigation toggles and dropdown controls retain their normal appearance and hover treatment. Other surfaces and fields retain their existing material. `default` restores the existing material behavior inside an explicitly configured section.

Liquid uses transparent neutral backing (12% by default), backdrop blur without added saturation, white reflections and a press/release scale transition. It adds no accent or semantic tint. Its opaque fallback is also neutral. Existing `data-motion` settings control timing and movement. Reduced motion, reduced transparency, increased contrast, forced colors and print take priority, including within local settings. This is a CSS approximation, without optical refraction or pointer tracking.

The customizer, isolated previews, standalone demos, starter, module/token/attribute references and dedicated guide include the feature. Firefox scope-root guards and stylesheet invalidation prevent stale semantic/material paint. Default previews now preserve their documented size, gap and width settings when opening the customizer.

## Menu and clear Liquid correction

Navigation toggles and standalone dropdown controls are excluded from every button-material paint, state and preference selector, including local action roots. Liquid now has 12% neutral backing, blur without saturation, white reflections and theme text. Accent and semantic variants do not tint it. Per-action fallback values keep increased-contrast and unsupported-blur backing neutral, including secondary actions. The guide includes a patterned-background transparency example and documents contrast review over custom images.

The final correction checks cover 24 button-material cases plus documentation navigation and selected downloads. Global/scoped navigation is compared with the module absent in normal, hovered and pressed states, across all six settings and both themes. Neutral/translucent Liquid is checked across eight palettes and semantic variants; the 480-button rendered contrast check is retained.

All 29 targeted checks pass in each of Chromium, Firefox and Linux WebKit (87 total), together with all 60 unit, four installed-package and three installed-package browser checks. CSS compilation and the 486-page documentation build pass. Twelve light/dark desktop/mobile screenshots were generated; representative finish and navigation images were inspected in all three engines. Mobile overflow checks are clear.

Firefox's emulation left contrast CSS stale when contrast and reduced motion were changed together in one protocol request. The same failure was reproduced with the previous module. The test now sends separate preference updates and retains all final-state assertions. Additional fresh-page checks independently verify system More Contrast on primary, secondary, danger and local Auto actions. This does not sign off physical OS preference changes.

Core minified gzip remains 15,234 bytes; the corrected optional module is 2,945 bytes gzip. Package metadata remains 1.1.0 and the work remains a 1.2 development preview.

## Visual review and remaining release gates

Desktop and mobile screenshots were generated in all three engines for light/dark finishes and pressed Liquid buttons. Representative images from each engine were inspected; no horizontal overflow was detected.

Real Safari/iPhone touch interaction, release feel and reduced-transparency behavior still require device checks for this feature. Keyboard `:active` appearance follows the browser: Firefox on Linux can activate a button with Space without exposing its pressed CSS state. Native activation remains intact.

This is a 1.2.0 development preview. Package metadata remains 1.1.0 until release preparation; existing npm/GitHub release assets are not replaced. This record does not sign off physical-device, assistive-technology or release gates from previous revisions.
